# Quarkus Queryable

[![Maven Central](https://img.shields.io/maven-metadata/v?metadataUrl=https%3A%2F%2Frepo.maven.apache.org%2Fmaven2%2Fdev%2Fqueryable%2Fquarkus-queryable%2Fmaven-metadata.xml&label=maven%20central)](https://central.sonatype.com/artifact/dev.queryable/quarkus-queryable)

Queryable is a Quarkus extension that adds annotation-driven collection filters
to Hibernate ORM REST Data with Panache.

Standard CRUD, count, OpenAPI and transaction handling are generated by
`quarkus-hibernate-orm-rest-data-panache`. Queryable contributes the collection
`GET` endpoint and its richer query language.

> Status: preview. The project is being prepared for Quarkiverse onboarding.

## Install

```xml
<dependency>
    <groupId>dev.queryable</groupId>
    <artifactId>quarkus-queryable</artifactId>
    <version>4.0.3</version>
</dependency>
```

Applications also select their JDBC driver and JSON extension, for example:

```xml
<dependency>
    <groupId>io.quarkus</groupId>
    <artifactId>quarkus-jdbc-postgresql</artifactId>
</dependency>
<dependency>
    <groupId>io.quarkus</groupId>
    <artifactId>quarkus-rest-jackson</artifactId>
</dependency>
```

## Minimal example

```java
@Entity
@QRs("/api/developers")
@QOrderBy("surname asc")
public class Developer extends PanacheEntityBase {

    @UuidGenerator
    @Id
    @QList
    public String uuid;

    @QLike
    public String name;

    @QLike
    public String surname;

    @QList
    public String team_uuid;

    @QLogicalDelete
    public boolean active = true;
}
```

The extension exposes:

```text
POST   /api/developers
GET    /api/developers/{id}
PUT    /api/developers/{id}
DELETE /api/developers/{id}
GET    /api/developers/count
GET    /api/developers?like.surname=pi
GET    /api/developers?obj.team_uuid=<uuid>
```

## Extension points

Custom filters go in `service.filters`:

```java
@ApplicationScoped
public class DeveloperFilter implements QueryableFilter<Developer> {

    @Override
    public void contribute(QueryableFilterContext<Developer> context) {
        // add Criteria API predicates
    }
}
```

REST lifecycle callbacks go in `service.rs`:

```java
@PrePersist
void audit(Developer developer) {
    developer.creationDate = LocalDateTime.now();
    developer.creationUser = identity.getPrincipal().getName();
}

@PostUpdate
void notify(Developer developer) {
    // external side effect, executed after commit
}
```

Queryable also supports existing Hibernate filters with
`@QFilter`; see [Query filters](docs/modules/ROOT/pages/filters.adoc).

Security remains standard Quarkus configuration:

```properties
quarkus.http.auth.permission.developers.paths=/api/developers/*
quarkus.http.auth.permission.developers.policy=authenticated
quarkus.http.auth.permission.developers-list.paths=/api/developers
quarkus.http.auth.permission.developers-list.policy=authenticated
```

## AI agent skills

The portable [Agent Skills](https://agentskills.io/) in `skills/` help coding
agents work with Queryable:

- `quarkus-queryable`: generated endpoints and filters.
- `quarkus-queryable-lifecycle`: REST listeners, validation and auditing.
- `quarkus-queryable-development`: maintainers changing this extension.

To install the two consumer skills into a project for supported agents including
Codex, Claude Code, Cursor, GitHub Copilot, Gemini CLI and OpenCode, use Node.js
22.20 or later and run:

```bash
npx skills add queryabledev/quarkus-queryable --skill quarkus-queryable quarkus-queryable-lifecycle
```

Select the agents when prompted; add `-g` for a user-level installation. To
install the maintainer skill, select `quarkus-queryable-development` instead.
See the [skills CLI](https://github.com/vercel-labs/skills) for agent selection,
updates and other options. The command uses the repository's default branch;
these skills become available there after the changes are published. Choose a
release or branch matching your application when appropriate. The consumer
skills currently describe the 4.0.3 API.

Alternatively, copy the complete skill directories, including `references/`,
from a checkout into the agent's project skill directory: `.agents/skills/`
for Codex, Cursor, Gemini CLI and OpenCode; `.claude/skills/` for Claude Code;
or `.github/skills/` for GitHub Copilot. Consult your agent's documentation
for personal locations and discovery behavior. Restart or reload the agent if
it does not discover the skills immediately.

## Build and test

```bash
mvn clean install
```

The reactor contains a complete Quarkus integration application. A standalone
consumer test simulates a separate real application:

```bash
mvn install -DskipTests
mvn -f consumer-tests/pom.xml test
```
